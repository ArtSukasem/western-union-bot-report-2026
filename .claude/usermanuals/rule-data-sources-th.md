สรุปจากโค้ดใน `src/BotReport2026/` (v0.2.0) ณ วันที่ 23 ต.ค. 2026 — บอกว่าแต่ละ rule

## 2. คอลัมน์ RSP ที่ใช้ร่วมกัน

ทุก rule ที่ใช้ RSP อ่านคอลัมน์ชุดเดียวกัน โดยตำแหน่งต่างกันระหว่างขาเข้า / ขาออก

| ข้อมูล | IB (ขาเข้า — ผู้รับเงิน) | OB (ขาออก — ผู้ส่งเงิน) | ใช้ทำอะไร |
|---|---|---|---|
| MTCN | cl1 | cl1 | เลขอ้างอิง (DS_SBE field 3) |
| สถานะรายการ | cl2 | cl2 | กรองเฉพาะ `PAID` / `UNPAID` (ตั้งค่าได้) |
| วันที่ | cl5 Pay_Date | cl3 Send_Date | 202, 203, 208, 209 |
| เวลา | cl6 Pay_Time | cl4 Send_Time | 209 |
| ยอดเงิน (Principal) | cl12 Pay_Principal | cl8 Send_Principal | 202, 203, 206, 208 และ DS_SAE field 12 |
| รหัสสาขา | cl22 | cl16 | 203-Retail (เฉพาะ OB — ตัดสาขาออนไลน์ออก), 206, DS_SAE field 11 และ 15 |
| ชื่อ | cl60 | cl25 | 101 (UN), 212, 301 และ DS_SBE field 11 |
| นามสกุล | cl61 | cl26 | 101 (UN), 212, 301 และ DS_SBE field 13 |
| **เลขประจำตัว (Person ID)** | **cl74** | **cl39** | **ใช้จัดกลุ่ม "รายบุคคล" ในทุก rule** และ DS_SBE field 8 |
| อาชีพ (dropdown) | cl89 | cl54 | 203-Retail (เฉพาะ OB cl54) และ DS_SBE field 16 — เทียบตรงทุกตัวอักษรก่อน |
| อาชีพ (พิมพ์เอง) | cl114 | cl104 | ใช้เมื่อ cl89 / cl54 ไม่ตรงกับไฟล์ lookup (รวม `OTHERS`) — เทียบแบบ fuzzy ≥ 80% |
| สัญชาติ | cl66 | cl31 | DS_SAE field 4 |
| ที่อยู่ (หลายบรรทัด) | cl68–cl73 | cl33–cl38 | DS_SBE field 14 |
| รหัสไปรษณีย์ | cl73 | cl38 | DS_SBE field 15 |
| ประเทศที่ออกบัตร | cl77 | cl42 | DS_SBE field 7 |
| ประเภทบัตร (A = passport, B = บัตรประชาชน) | cl78 | cl43 | DS_SBE field 6 |

**การกรองตอนอ่าน RSP (มีผลกับทุก rule):**
- เก็บเฉพาะแถวที่ cl2 เป็น `PAID` หรือ `UNPAID` (ปรับได้ใน `RspIncludedStatuses`)
- ข้ามแถวที่ MTCN ว่าง
- ข้ามแถวที่ยอดเงินเป็น 0 หรือติดลบ

## 3. รายละเอียดแต่ละ Rule

ค่าที่ตั้งได้แสดงเป็น **ค่าที่ใช้อยู่ตอนนี้** (จาก `config.json` ของ dev build) และค่า default ในวงเล็บ

### Rule 101 — ตรงกับ Sanction List (UN / TH-CFR)

| | |
|---|---|
| **Lookup** | `lookups/saction_list.xlsx` (sheet UN และ TH) |
| **ข้อมูลที่ใช้** | RSP เดือนรายงาน (IB + OB): Person ID (cl74/cl39), ชื่อ + นามสกุล (cl60+cl61 / cl25+cl26) |
| **ไม่ใช้** | RSP ย้อนหลัง, Transaction Report |

**วิธีคำนวณ**
1. จัดกลุ่มรายการเดือนรายงานตาม Person ID
2. **TH / CFR:** ถ้า Person ID ตรงกับ IDENTITY_ID (sheet TH, cl10) → เข้าเกณฑ์ (**เทียบเฉพาะเลข ID ไม่ดูชื่อ**)
3. **UN:** ถ้า Person ID ตรงกับ NUMBER (sheet UN, cl10) **และ**ชื่อตรงกับ FIRST_NAME ของ ID นั้น (sheet UN, cl5 แยกชื่อแฝงด้วย `;`) → เข้าเกณฑ์
   - ชื่อนับว่าตรง ถ้า "ชื่อ นามสกุล" จาก RSP มีชื่อแฝงอยู่ข้างใน หรือชื่อแฝงมี "ชื่อ นามสกุล" อยู่ข้างใน (ไม่สนตัวพิมพ์เล็ก-ใหญ่)
4. ถ้าเข้าเกณฑ์ → รายงาน**ทุกรายการ**ของคนนั้นในเดือนรายงาน (IB และ OB รวมกัน)
   - DS_SBE field 4 = **`101;211`**
   - DS_SBE field 5 = **"พบว่าธุรกรรม ถูกนำไปใช้หรือเกี่ยวข้องในการประกอบอาชญากรรมและมีความเชื่องโยงในลักษณะที่มีการทำรายการผิดปกติ เช่น บัญชีที่ถูกออกหมายอายัด"**
     (ข้อความกำหนดไว้ในโค้ด ไม่ได้อ่านจาก `behavior_descriptions.xlsx`)

**DS_SAE:** ระบบกรอกผลให้ล่วงหน้าและล็อกไว้ — field 6 = `1 = ...พบว่าเป็นพฤติกรรมที่ผิดปกติ`,
field 7 = `รายชื่ออยู่ใน CFR`, field 9 = วันที่รันรายงาน

### Rule 202 — มูลค่าธุรกรรมเฉลี่ยต่อเดือนสูงกว่าที่ผ่านมา

| | |
|---|---|
| **Lookup** | ไม่มี |
| **ข้อมูลที่ใช้** | RSP เดือนรายงาน + RSP ย้อนหลัง: Person ID, วันที่ (cl5/cl3), ยอดเงิน (cl12/cl8) |
| **ค่าที่ตั้งได้** | `Rule202PriorMonths` = **6** (6), `Rule202Multiplier` = **3** (3) |

**วิธีคำนวณ** (แยกขาเข้า IB และขาออก OB)
1. จาก RSP ย้อนหลัง รวมยอดเงินต่อเดือน แยกตาม (Person ID, ทิศทาง)
2. เลือก **6 เดือนล่าสุดที่มีรายการ** (เดือนที่ไม่มีรายการจะไม่ถูกนับ) แล้วหาค่าเฉลี่ยต่อเดือน
3. ถ้ายอดรวมในเดือนรายงาน **>** ค่าเฉลี่ย × 3 → เข้าเกณฑ์
4. คนที่ไม่มีประวัติย้อนหลังในทิศทางนั้น (ลูกค้าใหม่) → ไม่ถูกตรวจ
5. รายงานทุกรายการเดือนรายงานของทิศทางที่เข้าเกณฑ์ (ถ้าเข้าทั้งสองทิศทางจะรายงานรวมกัน)

### Rule 203 — ไม่สอดคล้องกับ Profile รายได้ / อาชีพ

แบ่งเป็น 2 ส่วน

#### 203-Online (ช่องทางออนไลน์)

| | |
|---|---|
| **Lookup** | ไม่มี |
| **ข้อมูลที่ใช้** | Transaction Report เดือนรายงาน: cl3 = MTCN, cl4 = Status, cl9 = ชื่อผู้ส่ง, cl12 = เลข ID ผู้ส่ง, cl17 = ยอดเงิน, cl24 = Error Reason |

**วิธีคำนวณ**
1. เก็บเฉพาะแถวที่ cl24 (Error Reason) **มีคำว่า `income`** (ไม่สนตัวพิมพ์ เช่น `r2110 proof of income required`)
2. และ cl4 (Status) เป็น `Approved`, `Received`, `Delivered` (ผ่าน EDD) หรือ `Refunded` (EDD ไม่ผ่าน)
   — สถานะอื่นรวมถึง `PENDING REFUND` ไม่นับ
3. ทุกแถวที่ผ่านเงื่อนไข → DS_SBE 1 แถวต่อ MTCN
   - field 8 = cl12, field 11 = cl9 (ชื่อทั้งก้อน)
   - field 6, 7, 13, 14, 15, 16 **ว่าง** เพราะ Transaction Report ไม่มีข้อมูลเหล่านี้
4. **DS_SAE:** กรอกให้ล่วงหน้าตาม Status (แก้ไขได้ทั้งหมด) และ field 5 = วันที่รันรายงาน

   | Status | field 6 ผลการตรวจสอบ | field 7 เหตุผล | 7.1 ระบุเหตุผล |
   |---|---|---|---|
   | Approved / Received / Delivered | `0 = ...ไม่เป็นพฤติกรรมที่ผิดปกติ` | ว่าง | ว่าง |
   | Refunded | `1 = ...เป็นพฤติกรรมที่ผิดปกติ` | `อื่น ๆ (ระบุ) (ให้พิมพ์เอง)` | `EDD ไม่ผ่าน` |

   ตอน export CSV ช่อง 7.1 จะไปแทน field 7 → field 7 ใน CSV = `EDD ไม่ผ่าน`

#### 203-Retail (หน้าร้าน)

| | |
|---|---|
| **Lookup** | `lookups/list_of_occupation_expected_monthly_income.xlsx` (cl1 ชื่ออาชีพ EN → คอลัมน์ `Expected Monthly Income`) |
| **ข้อมูลที่ใช้** | **RSP ขาออก (OB) เท่านั้น** เดือนรายงาน + ย้อนหลัง: Person ID (cl39), วันที่ (cl3), ยอดเงิน (cl8), รหัสสาขา (cl16), อาชีพ (cl54 + cl104) — ไม่ใช้ RSP ขาเข้า |
| **ค่าที่ตั้งได้** | `Rule203RollingMonths` = **3** (3), `Rule203Multiplier` = **3** (3), `Rule203ExcludedBranches` = **ATH170025, ATH170014** (ATH170025, ATH170014), `OccupationFuzzyThresholdPercent` = **80** (80), `Rule203OtherMonthlyIncome` = **49,999** (49,999) |

**วิธีคำนวณ** (คิดเฉพาะขาออก)
1. ใช้เฉพาะ RSP ขาออก และตัดรายการของสาขาที่อยู่ใน `Rule203ExcludedBranches` (สาขาออนไลน์ ATH170025, ATH170014) ออก
2. ช่วงเวลา = ตั้งแต่วันที่ 1 ของ (เดือนรายงาน − 3 เดือน) ถึงปัจจุบัน
   — **ได้เดือนรายงาน + 3 เดือนก่อนหน้า รวม 4 เดือน**
3. หารายได้ที่คาดหวังจากไฟล์ mapper โดยไล่ทีละรายการของคนนั้น (เดือนรายงานก่อน แล้วจึงย้อนหลัง)
   และใช้รายการแรกที่หาเจอ แต่ละรายการลองตามลำดับ
   1. **cl54** ตรงกับชื่ออาชีพในไฟล์ทุกตัวอักษร (ไม่สนตัวพิมพ์และช่องว่าง)
      — ค่า `OTHERS` / `OTHER` / ว่าง ถือว่าไม่ตรง
   2. ถ้าไม่ตรง → ใช้ **cl104** เทียบแบบ **fuzzy ≥ 80%** กับทุกชื่อในไฟล์ แล้วเลือกตัวที่คะแนนสูงสุด
      - คะแนน = 1 − (จำนวนตัวอักษรที่ต้องแก้ ÷ ความยาวของคำที่ยาวกว่า) โดยนับการสลับตัวอักษรที่อยู่ติดกันเป็น 1 ครั้ง
      - เช่น `HOUSEWIFT` → Housewife 89%, `HOUSE WIFE` → 90%, `RETRIED` → Retired 86%, `RETIREMENT` → 60% (ไม่ผ่าน)
   - **ถ้าหาไม่เจอ หรือแถวที่เจอไม่มีรายได้ (เช่นเป็นช่วง `0 – 5,000`) → ถือเป็นอาชีพอื่น ๆ
     ใช้รายได้ 49,999 บาท/เดือน** (`Rule203OtherMonthlyIncome`) แล้วตรวจต่อตามปกติ
     — log สรุปจำนวนคนที่ใช้ค่านี้ 1 บรรทัด
   - ถ้าคำสะกดผิดแบบเดิมเจอบ่อย (เช่น `MAID`, `TOURIST`) ให้เพิ่มเป็นแถวชื่อเรียกอื่นในไฟล์ lookup ได้เลยโดยไม่ต้องแก้โปรแกรม
4. ถ้ายอดรวมในช่วงเวลา **>** รายได้ต่อเดือน × 3 **และ**มีรายการในเดือนรายงาน → เข้าเกณฑ์
5. รายงานเฉพาะรายการ**เดือนรายงาน** (ที่ไม่ใช่สาขาออนไลน์) ของทิศทางที่เข้าเกณฑ์

### Rule 206 — ธุรกรรมในสาขาพื้นที่เสี่ยง

| | |
|---|---|
| **Lookup** | ไม่มี (รายชื่อสาขาอยู่ในหน้าตั้งค่า) |
| **ข้อมูลที่ใช้** | RSP เดือนรายงาน: รหัสสาขา (cl22/cl16), Person ID, ยอดเงิน |
| **ค่าที่ตั้งได้** | `Rule206HighRiskBranches` = **ATH160206** (ว่าง), `Rule206PrincipalThreshold` = **700,000** (700,000), `Rule206TxnCountThreshold` = **20** (20) |

**วิธีคำนวณ** (แยก IB / OB)
1. ถ้าไม่ได้ตั้งสาขาไว้ → ข้าม rule นี้
2. เลือกรายการเดือนรายงานที่ทำในสาขาที่กำหนด แล้วจัดกลุ่มตาม Person ID
3. ถ้ายอดรวม **≥** 700,000 บาท **หรือ**จำนวนครั้ง **≥** 20 ครั้ง → เข้าเกณฑ์
4. รายงานรายการ**ในสาขาเสี่ยง**ของทิศทางที่เข้าเกณฑ์

> ตอนนี้ตั้งสาขา `ATH160206` ไว้ ขณะที่ CLAUDE.md บอกว่า "ยังไม่มีสาขาที่เข้าข่าย" — ควรตรวจสอบว่าตั้งใจหรือไม่

| **ค่าที่ตั้งได้** | `Rule208SubThreshold` = **50,000** (50,000)<br>รายวัน: `DailyCount` = **10** (10), `DailyAmount` = **150,003** (150,000)<br>รายสัปดาห์: `WeeklyCount` = **20** (20), `WeeklyAmount` = **150,000** (150,000)<br>รายเดือน: `MonthlyCount` = **50** (50), `MonthlyAmount` = **150,000** (150,000) |

**วิธีคำนวณ** (แยก IB / OB)
1. เลือกเฉพาะรายการที่ยอดเงิน **< 50,000** บาท
2. จัดกลุ่มตาม Person ID แล้วตรวจ 3 ระดับ เข้าเกณฑ์ข้อใดข้อหนึ่งก็พอ
   - **รายเดือน:** จำนวนครั้ง **>** 50 **และ**ยอดรวม **≥** 150,000
   - **รายวัน:** มีวันใดวันหนึ่งที่จำนวนครั้ง **>** 10 **และ**ยอดรวม **≥** 150,003
   - **รายสัปดาห์** (สัปดาห์ ISO จันทร์–อาทิตย์): มีสัปดาห์ใดที่จำนวนครั้ง **>** 20 **และ**ยอดรวม **≥** 150,000
3. รายงาน**ทุกรายการที่ยอดต่ำกว่า 50,000** ของคนนั้นในเดือนรายงาน (ทิศทางที่เข้าเกณฑ์)

> `DailyAmount` ตั้งไว้ 150,003 ไม่ใช่ 150,000 — น่าจะพิมพ์ผิด ควรตรวจสอบ

## 4. กติกาที่ใช้ร่วมกันทุก Rule

### 4.1 แยกขาเข้า / ขาออก
Rule 202, 203-Retail, 206, 208, 209 ตรวจ IB และ OB **แยกกัน**
- เข้าเกณฑ์ทิศทางเดียว → รายงานเฉพาะรายการทิศทางนั้น
- เข้าเกณฑ์ทั้งสองทิศทาง → รายงานทั้งสองทิศทางรวมกัน

Rule 101 และ 212 รายงานทุกรายการของคนนั้นโดยไม่แยกทิศทาง

### 4.2 MTCN ซ้ำหลาย Rule
DS_SBE มี 1 แถวต่อ MTCN ถ้า MTCN เดียวเข้าหลาย rule จะรายงานเป็น rule ที่**มาก่อน**ตามลำดับนี้

**101 → 202 → 203 → 206 → 208 → 209 → 212 → 301**

rule ที่ถูกตัดออกจะขึ้นใน log เช่น `MTCN 0947566663: เข้าเกณฑ์ทั้ง 202-OB และ 209-OB — รายงานเป็น 202`

### 4.3 ตรวจเลขบัตรประชาชน
แถวที่ field 6 เป็นบัตรประชาชน (cl78/cl43 = `B`) แต่ field 8 ไม่ใช่ตัวเลข 13 หลัก
→ ยังรายงานตามปกติ แต่บันทึกลง `report-results/error.xlsx` (พร้อมชื่อไฟล์และแถวต้นทาง)
