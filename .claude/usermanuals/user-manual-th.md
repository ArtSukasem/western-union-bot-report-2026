# BotReport 2026 — คู่มือการใช้งาน (ภาษาไทย)

โปรแกรมสำหรับงานกำกับดูแลรายเดือน ใช้ตรวจสอบข้อมูลธุรกรรมโอนเงินและจัดทำ
ชุดข้อมูล 2 ชุดที่ต้องนำส่งธนาคารแห่งประเทศไทย (ธปท.) ตามข้อกำหนด SBR Dataset:

| ชุดข้อมูล | รหัส | รายละเอียด |
|---|---|---|
| DS_SBE | 1.1 | ข้อมูลพฤติกรรมที่ผิดปกติรายลูกค้า (ก่อนทำ EDD) |
| DS_SAE | 1.2 | ผลการตรวจสอบ EDD (Enhanced Customer Due Diligence) |

กำหนดส่งรายงาน **ภายใน 15 วัน นับจากวันที่ของข้อมูล** (เช่น รายงานข้อมูลเดือนพฤษภาคม
ต้องส่งภายในวันที่ 15 มิถุนายน)

---

## 1. การเริ่มใช้งานโปรแกรม

1. รับไฟล์โปรแกรมรุ่นล่าสุด — จากโฟลเดอร์ `Releases/` (แตกไฟล์ zip) หรือรันจาก
   ซอร์สโค้ดโดยลง .NET 8 แล้วสั่ง
   `dotnet run --project program/BotReport2026/BotReport2026.csproj`
2. เปิดโปรแกรม **BotReport2026.exe** เมื่อเปิดครั้งแรก โปรแกรมจะสร้างโฟลเดอร์ที่
   จำเป็นไว้ข้าง ๆ ตัวโปรแกรมให้อัตโนมัติ:
   - `input-rsp/`
   - `input-transaction-report/`
   - `lookups/`
   - `mapper/`
   - `report-results/`
3. ต้องเก็บตัวโปรแกรมไว้ในตำแหน่งเดิมของโครงสร้างโฟลเดอร์ที่แตกไฟล์มา — ห้ามย้าย
   เฉพาะไฟล์ `.exe` ไปไว้โฟลเดอร์อื่นเพียงไฟล์เดียว ไม่เช่นนั้นโปรแกรมจะหา
   `input-rsp/`, `lookups/` ฯลฯ ไม่เจอ

ไม่ต้องติดตั้งโปรแกรมเพิ่ม ไม่ต้องใช้สิทธิ์ผู้ดูแลระบบ และไม่ต้องเชื่อมต่ออินเทอร์เน็ต

## 2. ตำแหน่งที่ต้องวางไฟล์

| โฟลเดอร์ | ไฟล์ที่ต้องวาง |
|---|---|
| `input-rsp/` | ไฟล์ `RSP_Inbound_*` / `RSP_Outbound_*` ของเดือนที่รายงาน และเดือนก่อนหน้า |
| `input-transaction-report/` | ไฟล์ `Transaction-Report *` ของเดือนที่รายงาน (ช่องทางออนไลน์) — ควรเก็บของเดือนก่อนหน้าไว้ด้วย |
| `lookups/` | `saction_list.xlsx` (รายชื่อ UN และ TH sanction) และไฟล์รายชื่อบุคคลอาชญากรรมทางการเงิน/พฤติกรรมลูกค้าหน้าร้านน่าสงสัย |
| `mapper/` | ไฟล์ตารางเทียบอาชีพ → รายได้ต่อเดือนที่คาดหวัง |
| `report-results/` | ที่เก็บไฟล์ผลลัพธ์ `DS_SBE_yyyyMM.xlsx` และ `DS_SAE_yyyyMM.xlsx` หลังรันเสร็จ |

**การตั้งชื่อไฟล์**: โปรแกรมจะจับคู่ไฟล์จาก **ชื่อขึ้นต้น (prefix) เท่านั้น** —
นามสกุลไฟล์ไม่มีผล (จะเป็น `.xlsx`, ไม่มีนามสกุลเลยก็ได้) ขอเพียงเนื้อไฟล์เป็น
Excel จริง และชื่อไฟล์ขึ้นต้นถูกต้อง:

- `RSP_Inbound...` → ขาเข้า (รับเงิน)
- `RSP_Outbound...` → ขาออก (ส่งเงิน)
- `Transaction-Report...` → ธุรกรรมช่องทางออนไลน์

เดือนของไฟล์อ่านจากชื่อไฟล์เอง (ตัวย่อเดือนภาษาอังกฤษ 3 ตัว + ปี 2 หลัก เช่น
`May26`, `Apr_26`) หากโปรแกรมหาเดือนจากชื่อไฟล์ไม่เจอ จะถือว่าเป็นไฟล์
**ย้อนหลัง** ไว้ก่อนเพื่อความปลอดภัย ไม่ใช่เดือนที่รายงาน

**ควรเก็บไฟล์ RSP ย้อนหลังไว้หลายเดือนใน `input-rsp/`** เนื่องจาก 2 กฎต้องใช้
ข้อมูลย้อนหลัง: กฎ 202 ใช้สูงสุด 6 เดือนก่อนหน้า (ค่าเริ่มต้น), กฎ 203 (retail)
ใช้ 3 เดือน ไม่จำเป็นต้องลบไฟล์เดือนที่ไม่ได้รายงานออก โปรแกรมจะแยกเป็น
"เดือนที่รายงาน" กับ "ย้อนหลัง" ให้เองอัตโนมัติ

โปรแกรมไม่มีปุ่มเลือกไฟล์ในตัว (file picker) — ต้องคัดลอกไฟล์เข้าโฟลเดอร์โดยตรง
(ผ่าน Windows Explorer หรือลากวาง) แล้วกดปุ่ม 🔄 **โหลดใหม่** ในโปรแกรม

## 3. สามแท็บหลักของโปรแกรม

### แท็บ 1 — เลือกไฟล์ (📁 เลือกไฟล์)

![แท็บ 1 — เลือกไฟล์](images/tab1-file-selection.png)

- แสดง **เดือนที่รายงาน (auto)** ที่ตรวจพบโดยอัตโนมัติไว้ด้านบน
- ส่วน **ไฟล์อ้างอิง**: แสดง ✅ หรือ ❌ ของไฟล์อ้างอิงทั้ง 3 ไฟล์ (ตารางเทียบอาชีพ,
  sanction list, รายชื่ออาชญากรรม/หน้าร้านน่าสงสัย) หากขึ้น ❌ หมายความว่ากฎที่
  เกี่ยวข้องจะถูกข้ามหรือทำงานไม่ครบสำหรับรอบนี้ — แต่ **ไม่ทำให้การรันหยุด**
- มี 2 ช่องแสดงไฟล์ RSP ขาเข้า/ขาออกของเดือนที่รายงาน 1 ช่องแสดงไฟล์
  Transaction Report ของเดือนที่รายงาน และอีก 2 ช่องแสดงไฟล์ RSP **ย้อนหลัง**
  ขาเข้า/ขาออก ที่ใช้สำหรับกฎที่ต้องดูข้อมูลย้อนหลัง
- 🔄 **โหลดใหม่** — สแกนโฟลเดอร์ input ทั้งสองใหม่อีกครั้ง (ใช้เมื่อเพิ่มไฟล์
  ระหว่างที่เปิดโปรแกรมค้างอยู่)
- ปุ่ม 📂 **เปิดโฟลเดอร์ ...** — เปิดโฟลเดอร์ที่เกี่ยวข้องใน Explorer เพื่อความ
  สะดวกในการวางไฟล์โดยไม่ต้องไปหาที่อยู่เอง

### แท็บ 2 — ตั้งค่า (⚙️ ตั้งค่า)

![แท็บ 2 — ตั้งค่า](images/tab2-settings.png)

แต่ละกฎมีกล่องของตัวเอง แสดงค่าตัวเลขที่ปรับได้ (ดูความหมายในหัวข้อที่ 5
ด้านล่าง) ส่วนกฎ 101, 212, และ 301 ไม่มีค่าตัวเลขให้ปรับ เพราะเป็นกฎแบบ
จับคู่รายชื่อ แสดงไว้เพื่อทราบข้อมูลเท่านั้น

- 💾 **บันทึกตั้งค่า** — บันทึกลง `config.json` ทันที (ไฟล์อยู่ข้าง ๆ ตัวโปรแกรม)
- 📂 **โหลดตั้งค่า** — โหลดค่าจาก `config.json` กลับมา ทิ้งการแก้ไขที่ยังไม่ได้
  บันทึกบนหน้าจอ

ค่าตั้งค่าจะถูกบันทึกอัตโนมัติทุกครั้งที่กดรันรายงานด้วย ไม่ว่าจะกดบันทึกไว้
ก่อนหรือไม่ก็ตาม

### แท็บ 3 — รันและผลลัพธ์ (▶ รันและผลลัพธ์)

![แท็บ 3 — รันและผลลัพธ์ หลังรันเสร็จ](images/tab3-run-output.png)

- ตัวเลือก **เดือนที่รายงาน** (MM/YYYY) — เป็นจุดควบคุมหลักว่ากำลังรายงานเดือนไหน
  เมื่อเปลี่ยนเดือนตรงนี้ แท็บ 1 จะจัดกลุ่มไฟล์ใหม่ให้ตรงกันอัตโนมัติ
- **▶ รันรายงาน** — เริ่มประมวลผล ปุ่มนี้จะถูกปิดระหว่างที่กำลังรันอยู่
- **ยกเลิก** — หยุดการรัน ณ จุดตรวจสอบที่ปลอดภัยถัดไป (ระหว่างกฎแต่ละข้อ
  ไม่ใช่หยุดกลางคันขณะกฎกำลังทำงาน)
- กล่องบันทึกการทำงานสีดำแบบคอนโซลจะแสดงความคืบหน้าระหว่างรัน
- เมื่อรันเสร็จ จะแสดงที่อยู่ไฟล์ผลลัพธ์ทั้งสอง และปุ่ม **📂 เปิดโฟลเดอร์ผลลัพธ์**
  จะใช้งานได้

ปุ่มรันจะปฏิเสธไม่ให้เริ่มทำงาน **เฉพาะกรณี** ที่รายการไฟล์ RSP ขาเข้า, ขาออก,
และ Transaction Report ของเดือนที่รายงานว่างทั้งหมด — จะมีข้อความแจ้งเตือน
ปรากฏขึ้น โปรแกรม **ไม่ได้** ตรวจสอบไฟล์อ้างอิงล่วงหน้าก่อนรัน หากไฟล์ใดขาด
กฎที่เกี่ยวข้องจะแค่ไม่ให้ผลลัพธ์ (ยกเว้น sanction list และตารางเทียบอาชีพ ซึ่ง
หากไฟล์หายไปทั้งไฟล์ การรันจะหยุดพร้อมข้อผิดพลาด)

## 4. ขั้นตอนการทำงานรายเดือน (ทำครบตั้งแต่ต้นจนจบ)

1. คัดลอกไฟล์ RSP ขาเข้า/ขาออกของเดือนนี้ ใส่ใน `input-rsp/` (ไฟล์เดือนก่อนหน้า
   ที่มีอยู่แล้วจากรอบก่อนไม่ต้องลบออก)
2. คัดลอกไฟล์ Transaction Report ของเดือนนี้ ใส่ใน `input-transaction-report/`
3. ตรวจสอบว่า `lookups/` และ `mapper/` มีไฟล์ sanction list, รายชื่อ
   อาชญากรรม/หน้าร้านน่าสงสัย และตารางเทียบอาชีพ ที่เป็นเวอร์ชันล่าสุด
4. เปิดโปรแกรม (หรือกด 🔄 โหลดใหม่ หากเปิดค้างอยู่แล้ว)
5. ที่ **แท็บ 1**: ตรวจสอบว่าเดือนที่รายงานที่ตรวจพบอัตโนมัติถูกต้อง และไฟล์
   อ้างอิงทั้ง 3 ขึ้น ✅ ครบ ตรวจดูรายการไฟล์ว่าไปอยู่ในกลุ่ม "เดือนที่รายงาน"
   หรือ "ย้อนหลัง" ถูกต้อง
6. ที่ **แท็บ 2**: ตรวจสอบค่าตัวเลขต่าง ๆ — โดยทั่วไปใช้ค่าเริ่มต้นไว้ เว้นแต่
   ทีมกำกับดูแลตกลงให้ปรับเปลี่ยน (ดูหัวข้อที่ 5)
7. ที่ **แท็บ 3**: ตรวจสอบเดือนที่รายงานอีกครั้ง กด **▶ รันรายงาน** แล้วดู
   บันทึกการทำงานจนกว่าจะเสร็จ
8. กด **📂 เปิดโฟลเดอร์ผลลัพธ์** และตรวจสอบว่ามีไฟล์ `DS_SBE_yyyyMM.xlsx` และ
   `DS_SAE_yyyyMM.xlsx` พร้อมรหัสงวดข้อมูลในชื่อไฟล์ตรงตามที่คาดไว้
9. นำส่งไฟล์ทั้งสองผ่านระบบ BOT Data Acquisition System ภายในกำหนด
   (วันที่ของข้อมูล + 15 วัน)

## 5. กฎการตรวจจับแต่ละข้อทำอะไรบ้าง

กฎ 201, 204, 205, และ 210 อยู่นอกขอบเขตของโปรแกรมนี้ (ไม่เข้าเกณฑ์ต้องทำ)

| กฎ | ตรวจจับอะไร |
|---|---|
| **101** | ผู้ส่ง/ผู้รับตรงกับรายชื่อ sanction list ของ UN หรือ TH/CFR (UN ต้องตรงทั้งชื่อและเลขบัตร, TH ใช้เลขบัตรอย่างเดียว) |
| **202** | ยอดโอนรวมของบุคคลในเดือนนี้ มากกว่า **3 เท่า** ของค่าเฉลี่ยยอดโอนต่อเดือนใน 6 เดือนก่อนหน้า |
| **203 (ออนไลน์)** | ธุรกรรมออนไลน์ที่ถูกระงับเพื่อขอ "หลักฐานแสดงรายได้" แล้วภายหลังผ่าน EDD — รายงานพร้อมผล EDD |
| **203 (หน้าร้าน/Retail)** | ยอดโอนรวมของบุคคลในช่วง 3 เดือนย้อนหลัง มากกว่า **3 เท่า** ของรายได้ต่อเดือนที่คาดหวังตามอาชีพที่แจ้งไว้ |
| **206** | ธุรกรรมที่สาขาพื้นที่เสี่ยงชายแดนที่กำหนดไว้ เกิน 700,000 บาท/เดือน หรือเกิน 20 ครั้ง/เดือน (ปัจจุบันยังไม่มีสาขาที่ถูกกำหนดเป็นพื้นที่เสี่ยง) |
| **208** | "Structuring" — ทำธุรกรรมจำนวนมากที่ยอดต่ำกว่า 50,000 บาทเล็กน้อย ถี่ในวัน/สัปดาห์/เดือนเดียว จนยอดรวมเกินเกณฑ์ |
| **209** | บุคคลทำธุรกรรมต่อเนื่องกินเวลามากกว่า 16 ชั่วโมงภายในวันเดียว |
| **212** | ชื่อผู้ส่ง/ผู้รับตรงกับรายชื่อบุคคลอาชญากรรมทางการเงินที่ทราบ |
| **301** | ธุรกรรมตรงกับรายชื่อ "ลูกค้าหน้าร้านน่าสงสัย" โดย MTCN, เลขบัตร, หรือชื่อ |

**ขาเข้าและขาออกจะถูกคำนวณแยกจากกัน** สำหรับกฎ 202, 203 (Retail), 206, 208,
และ 209 เงินที่บุคคลหนึ่ง *รับเข้า* กับ *ส่งออก* จะไม่ถูกนำมารวมกันอีกต่อไป
— แต่ละทิศทางจะถูกตรวจสอบกับเกณฑ์แยกกัน หากมีเพียงทิศทางเดียวที่เกินเกณฑ์
จะรายงานเฉพาะธุรกรรมของทิศทางนั้น หากทั้งสองทิศทางเกินเกณฑ์เป็นอิสระต่อกัน
จะรวมเป็นรายการเดียวที่ครอบคลุมทั้งสองทิศทาง

ค่าตัวเลขทั้งหมดข้างต้นเป็น **ค่าเริ่มต้น** เท่านั้น สามารถปรับได้ทุกค่าที่
แท็บ 2 (ดูรายชื่อฟิลด์ทางเทคนิคทั้งหมดได้ที่
[04-configuration.md](../../program/.claude/instructions/04-configuration.md))

## 6. การแก้ไขปัญหาเบื้องต้น

| อาการ | สาเหตุที่เป็นไปได้ / วิธีแก้ |
|---|---|
| ขึ้นข้อความเตือน "กรุณาเลือกไฟล์อย่างน้อย 1 ไฟล์ก่อนรัน" เมื่อกดรัน | ไม่พบไฟล์ของ **เดือนที่รายงาน** เลย ตรวจสอบว่าชื่อไฟล์มีรหัสเดือนที่โปรแกรมอ่านได้ และเดือนที่เลือกในแท็บ 3 ตรงกับไฟล์ |
| ไฟล์อ้างอิงในแท็บ 1 ขึ้น ❌ | ไฟล์หายไปจาก `lookups/` หรือ `mapper/` หรือถูกเปลี่ยนชื่อ ใช้ปุ่ม 📂 เปิดโฟลเดอร์ ตรวจสอบ แล้ววางไฟล์ที่ถูกต้อง จากนั้นกด 🔄 โหลดใหม่ |
| กฎ 202 หรือ 203 ไม่ขึ้นรายการที่คาดว่าจะเจอ | ตรวจสอบว่า `input-rsp/` มีไฟล์ **เดือนก่อนหน้า** ครบเพียงพอ กฎเหล่านี้ต้องใช้ข้อมูลย้อนหลัง ไม่ใช่แค่เดือนที่รายงาน |
| เดือนที่รายงานที่ตรวจพบอัตโนมัติผิด | เปลี่ยนเองได้ที่ตัวเลือกเดือนในแท็บ 3 — แท็บ 1 จะจัดกลุ่มไฟล์ใหม่ให้ตรงกันอัตโนมัติ |
| ปรับค่าที่แท็บ 2 แล้วดูเหมือนไม่มีผล | ตรวจสอบว่ากด 💾 บันทึกตั้งค่าแล้ว (หรือกดรันได้เลย เพราะค่าตั้งค่าจะถูกบันทึกอัตโนมัติทุกครั้งที่เริ่มรัน) |
| โปรแกรมหาโฟลเดอร์ไม่เจอ / เปิดแล้วพัง | มักเกิดจากการย้ายไฟล์ `.exe` ออกจากโครงสร้างโฟลเดอร์เดิม ให้แตกไฟล์ zip จาก `Releases/` ใหม่แทนการคัดลอกเฉพาะ `.exe` |
| การรันหยุดพร้อมข้อผิดพลาดเกี่ยวกับ sanction list หรือตารางเทียบอาชีพ | ไฟล์ทั้งสองนี้จำเป็นต้อง **มีอยู่จริง** (ไม่ใช่แค่ต้องเป็นเวอร์ชันล่าสุด) มิเช่นนั้นการรันทั้งหมดจะหยุด ต่างจากรายชื่ออาชญากรรม/หน้าร้านน่าสงสัยที่แค่ข้ามกฎนั้นไปเฉย ๆ |

## 7. ข้อมูลเพิ่มเติม

- โปรแกรมจับคู่ไฟล์จาก **เนื้อหาไฟล์** ไม่ใช่นามสกุลไฟล์ — ไลบรารีที่ใช้อ่านไฟล์
  Excel (EPPlus) เปิดไฟล์ตามเนื้อหาจริง ดังนั้นไฟล์ `.xlsx` จริงจะใช้งานได้
  แม้นามสกุลจะถูกลบหรือเปลี่ยนไป ตราบใดที่ชื่อไฟล์ขึ้นต้นถูกต้อง
- ไฟล์ `config.json` (ค่าตั้งค่าที่บันทึกจากแท็บ 2) อยู่ข้าง ๆ ไฟล์ `.exe`
- ไฟล์ผลลัพธ์จะตั้งชื่อตามรูปแบบ `DS_SBE_yyyyMM.xlsx` /
  `DS_SAE_yyyyMM.xlsx` เสมอ เช่น `DS_SBE_202605.xlsx` สำหรับเดือนพฤษภาคม 2026
