# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

This is a **financial compliance automation** project for generating **Suspicious Behavior Reports (SBR)** submitted monthly to the Bank of Thailand (ธปท.) via the BOT Data Acquisition System. It processes money-transfer transaction data and flags suspicious behaviors per ธปท. SBR Dataset specification v2026.01.

There is **no existing code** — this project currently contains only input data, lookup tables, and requirements. Scripts must be built from scratch using Python.

## Output Reports

Two datasets are produced each month (due: Data Date + 15 days):

| Dataset | Code | Description | Layout |
|---|---|---|---|
| DS_SBE | 1.1 | ข้อมูลพฤติกรรมที่ผิดปกติรายลูกค้า (pre-EDD suspicious behavior) | 23 fields, **one row per MTCN** → `.csv` directly |
| DS_SAE | 1.2 | ผลการตรวจสอบ EDD (Enhanced Customer Due Diligence results) | 16 fields (+1 helper), one row per DS_SBE row → `.xlsm`, exports its own `.csv` |

Field-by-field layouts come from `requirements/version3/` sheets `(DS_SBE)` and
`(DS_SAE)`; see [.claude/instructions/03-data-formats.md](.claude/instructions/03-data-formats.md)
for how each is derived. Every field of DS_SBE is derived, so it is written
straight out as the submission `.csv`. DS_SAE needs staff EDD input first, so it
is a macro-enabled `.xlsm` carrying its own "export to CSV" button. An
`error.xlsx` appears only when a citizen ID fails validation.

**All CSVs are UTF-8 with BOM** — without the BOM, Excel on a Thai Windows reads
them as CP874 and Thai text is mangled. They are **pipe (`|`) separated**, with
**every field wrapped in double quotes** (embedded quotes doubled), and carry
**no header row** — data rows only.

## RSP Column Reference

RSP files have 121 columns. Key columns used across rules:

**Inbound (Receive money — IB):**
- cl1 = MTCN, cl5 = Pay_Date, cl6 = Pay_Time, cl12 = Pay_Principal
- cl22 = Pay_Agent_Account_ID (branch code)
- cl60 = Receiver_First_Name, cl61 = Receiver_Last_Name
- cl74 = Receiver_Id1_Number, cl89 = Receiver_Occupation, cl114 = free-text occupation (fuzzy-matched when cl89 has no exact lookup match)

**Outbound (Send money — OB):**
- cl1 = MTCN, cl3 = Send_Date, cl4 = Send_Time, cl8 = Send_Principal
- cl16 = Send_Agent_Account_ID (branch code; rule 203-Retail excludes `ATH170025`, `ATH170014`)
- cl25 = Sender_First_Name, cl26 = Sender_Last_Name
- cl39 = Sender_Id1_Number, cl54 = Sender_Occupation, cl104 = free-text occupation (fuzzy-matched when cl54 has no exact lookup match)

**Transaction Report columns:**
- cl4 = Status, cl24 = Error_Reason

## Detection Rules

> Rules 201, 204, 205, 210 are explicitly **out of scope** ("ไม่เข้าเกณฑ์").

### Rule 101 — Sanction / CFR List Match
- Match RSP sender/receiver name and ID against both UN and TH sanction lists for the reporting month.
- IB: match Receiver Firstname (cl60), Lastname (cl61), ID (cl74) against lists.
- OB: match Sender Firstname (cl25), Lastname (cl26), ID (cl39) against lists.
- Matching logic: name **and** ID match → flag all transactions for that person → DS_SBE.
- Reported in DS_SBE as field 4 = `101;211`, field 5 = the combined 101 + 211 description (`ClassificationTables.Rule101BehaviorDescription`), not the per-code text from `behavior_descriptions.xlsx`.

### Rule 202 — Abnormal Monthly Volume (Rolling Average)
- **Outbound only, and only branches `ATH170025`, `ATH170014`** (the online channel; cl16; branch list **user-configurable**) — inbound and every other branch are ignored, in both the history and the reporting month.
- Load all RSP files for N months prior + reporting month (default: 6 prior months; **user-configurable**).
- Group by person ID (OB: cl39). Compute average monthly principal for the prior N months (skip months with zero activity — new customers excluded).
- If reporting-month total principal > **3× average** (multiplier **user-configurable**) → flag all that person's in-scope transactions for the reporting month → DS_SBE.

### Rule 203 — Transactions Inconsistent with Income / Occupation Profile
**Online channel (Transaction Report):**
- Filter rows where cl24 (Error Reason) contains text starting with `Income` (e.g., `r2110 proof of income required`).
- If cl4 (Status) is `Approved`, `Received`, or `Delivered` → EDD already passed → report both DS_SBE **and** DS_SAE (DS_SAE field 6 pre-filled `0`).
- If cl4 (Status) is `Refunded` → EDD not passed → report both DS_SBE **and** DS_SAE, with DS_SAE field 6 = `1`, field 7 = the "อื่น ๆ (ระบุ)" option and 7.1 = `EDD ไม่ผ่าน`.

**Retail channel (RSP outbound only — inbound is not used; exclude online branches `ATH170025`, `ATH170014`):**
- Rolling 3 months (prior months; **user-configurable**).
- Look up occupation: cl89/cl54 exact match on the lookup's English name; if no match (incl. OTHERS) → cl114/cl104 fuzzy match ≥ **80%** (**user-configurable**) → expected monthly income from the lookup. The same match supplies DS_SBE field 16 from the lookup's `BoT code` column (no match → `2003500015`). No match with an income → occupation is "Others" → expected monthly income = **49,999 THB** (**user-configurable**) instead of skipping the person.
- If total outbound principal in the window > **3× expected monthly income** (multiplier **user-configurable**) → the person's reporting-month outbound transactions → DS_SBE.
- When that person's occupation is "Others" (the 49,999 fallback), their DS_SAE rows are pre-filled with field 6 = `1` (abnormal), left editable; everyone else's field 6 is left for staff.
- Branch account exclusion list is **user-configurable**.

### Rule 206 — Transactions in High-Risk Border Branches
- Currently no qualifying branches (no branches in 3 southern border provinces). Branch list is **user-configurable** for future use.
- Threshold: monthly principal ≥ **700,000 THB** or transaction count ≥ **20 times/month** (both **user-configurable**) → DS_SBE.

### Rule 208 — Structuring (High frequency, sub-threshold amounts)
- **Outbound only, and only branches `ATH170025`, `ATH170014`** (the online channel; cl16; branch list **user-configurable**) — inbound and every other branch are ignored.
- Filter transactions with principal < 50,000 THB (i.e., ≤ 49,999 THB).
- Flag if any of the following in the reporting month (**all thresholds user-configurable**):
  - > 8–10 times/day **and** daily total ≥ 150,000 THB
  - > 15–20 times/week **and** weekly total ≥ 150,000 THB
  - > 30–50 times/month **and** monthly total ≥ 150,000 THB
- → DS_SBE.

### Rule 209 — 24/7 Continuous Transactions
- **Outbound only, and only branches `ATH170025`, `ATH170014`** (the online channel; cl16; branch list **user-configurable**) — inbound and every other branch are ignored.
- Detect persons making transactions across ≥ **16–24 consecutive hours** within a single day (**threshold user-configurable**).
- → DS_SBE.

## Python Environment

```bash
pip install openpyxl pandas pypdf pdfplumber
```

All scripts should use `encoding='utf-8'` when writing files. Column headers in RSP/Transaction Report files have leading spaces — strip them when reading. RSP files have a **single header row** (row 1 = field names); data starts at row 2. Transaction Report files vary — production exports have one header row, older samples had two ("online" banner + field names) — so the reader locates the header by finding "MTCN" in cl3 rather than assuming. Header text is otherwise ignored: columns are indexed by position (cl1…cl121) as documented above.

Only RSP rows whose `cl2` Transaction_Status is **PAID or UNPAID** are reported (configurable).
